---
description: 盘点项目里散乱、重复、过时的文档，给出整理清单，确认后再动
---

盘点并整理这个项目的文档。**第 1 到 3 步只读不改，用户确认清单后才动手。**

1. 运行盘点：

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/skills/project-docs/scripts/check-docs.mjs" --audit
   ```

   输出包括每个 `.md` 的位置是否合规、行数、最后改动日期，以及检查发现的错误和提醒。

2. 逐个阅读位置不合规的文档，以及 `docs/` 下超过 30 天没动的文档，判断：
   - **类型**：功能或需求、计划、决策、架构、Bug 或任务、总结或报告、其他
   - **是否过时**：提到的文件、命令、函数、配置在代码里还在不在；描述的行为和代码是否一致
   - **是否重复**：有没有另一份文档在讲同一件事

3. 给用户一张整理清单，每行包括：原路径、类型、处理方式、目标路径、理由。处理方式只有这几种：
   - **保留**：位置和内容都没问题
   - **移动**：内容有效，位置不对
   - **合并**：和另一份重复，把独有且仍然正确的内容并入保留的那份
   - **删除**：已完成的计划、工作总结、过时且无替代价值的内容（git 历史里仍然查得到）
   - **转 issue**：Bug、任务、待办
   - **待确认**：判断不了是否过时或是否还有人用

   同时列出建议加进配置 `allow` / `ignore` 的路径（工具或测试按固定路径读取的文件）。

   **然后停下来等用户确认。**

4. 用户确认后执行：
   - 移动用 `git mv`，保留历史
   - 合并时保留原有事实，不改写含义；两份说法矛盾时以代码为准，代码判断不了的列出来交给用户
   - 不凭推测补全缺失的信息
   - 全仓库搜索被移动或删除文件的旧路径，改掉指向它们的链接

5. 更新索引并检查，直到没有错误：

   ```bash
   node scripts/check-docs.mjs --index
   node scripts/check-docs.mjs --check
   ```

6. 报告：移动了什么、合并了什么、删除了什么、哪些内容互相矛盾需要用户决定。整理作为一次独立的提交，不和代码改动混在一起；是否提交由用户决定。
